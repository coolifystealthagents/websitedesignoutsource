# Evidence-Based Content Calendars for Outsourced Website Teams

A daily article routine needs more than a list of titles. Each item should carry search intent, a defensible source plan, a reviewer, a distinct slug, and a release decision.

## Key Stats

- WCAG 2.2 contains 13 guidelines (W3C)
- Schema.org lists Article as a type for article content (Schema.org)
- A sitemap URL entry can contain one loc value (Sitemaps protocol)

## Key Takeaways

- Treat the calendar as a queue of decisions, not a quota.
- Screen titles against existing slugs and search intent.
- Retain source notes after publication.

## Methodology

The article uses official documentation to define the technical terms and applies them to a recurring editorial workflow. It does not infer traffic, ranking, or conversion performance from the sources.

## Calendar fields

Useful fields include target reader, problem, proposed title, canonical slug, planned sources, headline statistic if defensible, internal links, reviewer, due date, validation state, and disposition. A missing source plan should keep an item in research.

## Review rhythm

Review the queue for overlap before drafting. After drafting, validate frontmatter, links, source count, headings, metadata, and build behavior. Preserve rejected topics so they are not accidentally regenerated tomorrow.

## Frequently asked questions

### Should a calendar force a fixed number of articles?

No. A target can guide capacity, but a topic should remain unpublished when sources or distinct intent are not defensible.

### Who should approve a research article?

Name one editorial owner and record the evidence used for the decision.
