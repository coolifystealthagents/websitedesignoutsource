# Component Inventories for Site Migrations

An inventory gives a redesign team a shared map of templates, modules, states, and dependencies. It also exposes where a screenshot-based handoff is hiding behavior.

## What to record

List component name, purpose, source locations, content fields, variants, responsive states, accessibility rules, analytics dependencies, owner, and destination. Mark unknowns rather than silently guessing.

## Methodology

This process note synthesizes component, accessibility, and migration documentation. It is intended for planning and review, not as a claim about project savings.

## Key Stats

- WCAG 2.2 is organized around four principles (W3C)
- The HTML specification defines native interactive elements and states (WHATWG)

## Key Takeaways

- Inventory behavior as well as visual appearance.
- Record ownership and unresolved questions.
- Reconcile the inventory with post-build QA.

## Frequently asked questions

### Is a component inventory only for large sites?

No. Even a small site benefits from knowing which repeated patterns must remain consistent.

### What happens to unknowns?

Give each one an owner and resolution date; do not turn an assumption into an undocumented requirement.
