# Component Inventory Audits for Outsourced Website Production

A component inventory turns a design system into something a reviewer can inspect. Each entry should show purpose, states, inputs, responsive behavior, accessibility expectations, examples, and the owner of future changes.

## Key Stats

- WCAG 2.2 has 4 principles (W3C)
- CSS has 5 generic font families (W3C)
- Core Web Vitals has 3 metrics (web.dev)

## Key Takeaways

- Inventory behavior, not only screenshots.
- Tie each component to examples and acceptance checks.
- Record exceptions rather than hiding one-off variants.

## Methodology

The source set supplies formal references for accessibility, CSS, performance, and structured data. The inventory model is a practical interpretation for outsourced web production.

## Inventory fields

Record name, purpose, anatomy, content limits, states, inputs, responsive behavior, keyboard behavior, focus treatment, contrast expectation, example routes, code or design location, version, owner, and review status.

## Audit evidence

Review the component in at least one real page and one edge state. Confirm text expansion, focus movement, error handling, image behavior, and mobile layout. Link findings to the component entry so later changes remain traceable.

## Frequently asked questions

### Is a design screenshot a component specification?

No. It usually omits states, inputs, responsive behavior, and accessibility interaction.

### Who should maintain the inventory?

Assign an owner inside the company and require the external team to update the evidence with each accepted change.
