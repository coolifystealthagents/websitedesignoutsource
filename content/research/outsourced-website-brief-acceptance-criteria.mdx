# Acceptance Criteria for an Outsourced Website Brief

A brief is more useful when it describes how approval will be decided. Acceptance criteria connect audience needs to observable behavior across design, content, accessibility, performance, and handoff.

## Write criteria that can be checked

State the route or component, user action, expected result, environment, evidence, and owner. Avoid words such as polished or intuitive unless they are paired with a concrete review method.

## Methodology

This synthesis draws on web standards, service design, and software verification guidance. Criteria still need to be adapted to the site’s audience and risk.

## Key Stats

- WCAG 2.2 defines testable success criteria for web accessibility (W3C)
- OWASP ASVS publishes verification requirements for web applications (OWASP)

## Key Takeaways

- Put acceptance into the brief before production.
- Make evidence and environment explicit.
- Separate must-pass conditions from preferences.

## Frequently asked questions

### Who writes acceptance criteria?

The accountable owner should approve them, with input from design, content, engineering, and QA.

### Can criteria change after work starts?

Yes, but record the change, reason, impact, and new approval owner.
