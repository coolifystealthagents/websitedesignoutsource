# An Image Optimization Brief for Outsourced Web Teams

Images affect performance, meaning, accessibility, and editorial quality. A useful brief identifies the purpose of each image before anyone chooses a file format or compression setting.

## Record purpose and constraints

For each image, record role, subject, alternative text, crop behavior, maximum display size, source license, focal point, and fallback. Decorative images need a different treatment from informative images.

## Validate in context

Check the largest and smallest layouts, slow loading, high-density displays, dark or light surfaces, and content management behavior. Confirm that the chosen asset is not merely small but still legible and meaningful.

## Methodology

This note synthesizes web platform, accessibility, and performance documentation. It does not recommend a single universal format.

## Key Stats

- The HTML `img` element supports responsive image selection through `srcset` and `sizes` (WHATWG)
- WCAG requires text alternatives for meaningful non-text content (W3C)

## Key Takeaways

- Define meaning before compression.
- Test assets at their actual display sizes.
- Preserve licensing and source metadata.

## Frequently asked questions

### Should every image have alt text?

Every meaningful image needs an appropriate text alternative. Decorative images can use an empty alternative when implemented correctly.

### Is the smallest file always best?

No. The right asset balances clarity, meaning, compatibility, and transfer cost.
