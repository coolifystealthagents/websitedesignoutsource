# Content Migration Quality Controls for Website Redesigns

Migration is a data movement project with editorial consequences. A source inventory, explicit mapping, and post-import review are more dependable than a last-minute spot check.

## Build the inventory first

Record source URL, content type, owner, status, destination, redirect decision, metadata, media dependencies, and review state. Separate keep, revise, merge, and retire decisions so the implementation team does not infer editorial intent.

## Validate after import

Check titles, headings, links, images, structured data, canonical behavior, redirects, and representative templates. Compare counts by content type and retain an exception list for anything not mapped.

## Methodology

This note synthesizes search-engine documentation, accessibility guidance, and migration practice. It intentionally avoids promising ranking outcomes.

## Key Stats

- Google describes permanent redirects as signals for consolidating URLs (Google Search Central)
- WCAG includes text alternatives as a core accessibility requirement (W3C)

## Key Takeaways

- Decide content fate before the import script runs.
- Validate both records and rendered pages.
- Keep redirect and exception ownership explicit.

## Frequently asked questions

### Should every old URL redirect?

No. Map useful URLs to the closest relevant destination and document intentional retirements.

### Who approves deletions?

The content owner, not the migration implementer, should approve editorial removals.
