# Performance Budgets for Outsourced Website Projects

Performance budgets give an outsourced website team a shared definition of acceptable speed before implementation choices become expensive to reverse.

## Key Stats

- Core Web Vitals has 3 current metrics (web.dev)
- The recommended LCP threshold is 2.5 seconds or less (web.dev)
- The recommended INP threshold is 200 milliseconds or less (web.dev)

## Key Takeaways

- Define budgets by template and device, not only by an average site score.
- Keep lab tests and field data separate because they answer different questions.
- Require a regression note when a change crosses a budget.

## Methodology

This review uses web.dev metric definitions, the Chrome UX Report documentation, HTTP caching guidance, and platform specifications. Thresholds are quoted as current guidance from the cited sources. Delivery recommendations are an operational interpretation.

## Budget structure

Set targets for LCP, INP, CLS, transferred bytes, image weight, and third-party scripts. Record test URL, device class, connection profile, browser version, and build identifier. A budget is useful only when the test conditions are reproducible.

## Release evidence

An outsourced team should attach before and after measurements, the changed assets, and a short explanation of any regression. The owner can then trade performance against business requirements with visible evidence.

## Consolidated statistics

The cited Core Web Vitals guidance uses 3 metrics, with recommended thresholds of 2.5 seconds for LCP and 200 milliseconds for INP. These are thresholds, not a promise of a particular user outcome.

## Frequently asked questions

### Should a vendor report one score?

No. Report the metrics, test conditions, and distribution or field context so the result can be reproduced.

### What happens when a budget is exceeded?

Record the cause, owner, expected remediation, and approval. Do not silently change the budget after the test.
