# Form QA Research for Outsourced Website Projects

Forms combine content, accessibility, validation, privacy, and delivery. A good QA plan tests the complete journey rather than only whether a submit button responds.

## Key Stats

- WCAG 2.2 has 4 principles (W3C)
- HTML defines 3 common constraint validation states used in this workflow: valid, invalid, and suffering from a constraint violation (WHATWG)
- GDPR Article 5 lists 7 principles for processing personal data (EUR-Lex)

## Key Takeaways

- Test empty, malformed, boundary, duplicate, and successful submissions.
- Check labels, focus, errors, consent, transport, storage, and notifications.
- Use synthetic test data and retain an evidence trail.

## Methodology

This synthesis uses WCAG 2.2, the HTML specification, GDPR principles, WAI forms guidance, and OWASP validation guidance. The count of GDPR principles comes from Article 5. The QA model is operational guidance and not legal advice.

## Test matrix

Create cases for keyboard-only use, screen reader announcements, mobile input, server rejection, timeout, duplicate submission, and recovery. Record expected and observed outcomes separately.

## Handoff controls

The delivery team should document endpoint, fields, validation rules, retention, notification path, and failure behavior. The company should approve destinations and any personal-data collection before release.

## Consolidated statistics

The cited material identifies 4 WCAG principles, 3 validation state categories used here, and 7 GDPR Article 5 principles. These counts do not measure form conversion or compliance.

## Frequently asked questions

### Is client-side validation enough?

No. Server-side validation and safe handling are required because client-side behavior can be bypassed.

### What data should be used in tests?

Use synthetic data that exercises the rule without exposing a real person's information.
