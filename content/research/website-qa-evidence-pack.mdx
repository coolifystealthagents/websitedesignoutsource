# What a Website QA Evidence Pack Should Contain

QA becomes faster when every change arrives with the same evidence. The pack should let an approver reproduce the claim, understand its scope, and see what remains open.

## The minimum record

Include change summary, affected routes, acceptance criteria, browser and viewport assumptions, test data, screenshots or recordings where useful, automated results, manual checks, defects, and approval status. Add commit or build identity when the workflow supports it.

## Evidence is not decoration

A screenshot can show appearance but not keyboard order, loading behavior, semantics, or data handling. Pair visual proof with a short test log and link each finding to a route or component.

## Methodology

This synthesis uses official testing guidance and established usability references. It does not stand in for product-specific risk assessment or security review.

## Key Stats

- WCAG recommends evaluation by a combination of automated and human checks (W3C)
- OWASP ASVS is organized into verification requirements for web applications (OWASP)

## Key Takeaways

- Make scope and environment explicit.
- Record failures as well as passes.
- Preserve evidence with the change record.

## Frequently asked questions

### How long should evidence be retained?

Long enough to support the agreed review, audit, and rollback window. The owner should set the retention rule.

### Are videos required?

No. Use the least costly evidence that proves the acceptance criterion.
