# Accessibility Review Triage for an Outsourced Website

Accessibility triage should help a team fix the obstacle that blocks a visitor’s task. Sort findings by affected task, evidence, severity, owner, and retest state rather than by the order produced by an automated scanner.

## Triage record

| Field | Example |
| --- | --- |
| Task | Open navigation or submit form |
| Barrier | Missing label or unavailable focus |
| Evidence | Route, setup, steps, result |
| Owner | Named implementer and approver |
| Retest | Same task and nearby task |

## Methodology

This synthesis uses W3C WCAG 2.2, WAI testing guidance, MDN, WebAIM, Google, OWASP, and NIST. Numeric claims are limited to standard counts or the cited WebAIM study. Triage recommendations are operational guidance, not a conformance certification.

## Key Stats

- WCAG 2.2 has 4 principles (W3C)
- WCAG 2.2 has 13 guidelines (W3C)
- WebAIM Million 2025 reported detected failures on 94.8% of tested homepages (WebAIM)

## Key Takeaways

- Start with the task and barrier, not the tool label.
- Combine automated checks with keyboard and user-task review.
- Keep exceptions visible and retain the final approval record.

## Findings sections

### Automated findings

Use scanners for repeatable signals such as missing names, contrast warnings, and structural issues. Confirm the finding in the actual page and remove false positives with a short explanation. Never turn a tool count into a claim about every accessibility barrier.

### Manual tasks

Run keyboard navigation, zoom, focus, form, heading, and error tasks. W3C explains that accessibility depends on people with different abilities and situations, so a screenshot or automated score cannot close every risk.

### Fix and retest

Assign one owner, one expected result, and one retest date. After a fix, repeat the original task and one related task. The company owner should decide whether a known exception is acceptable for the release.

## Frequently asked questions

### Is an automated accessibility score a pass?

No. It is one signal. Manual interaction and user-task review are still needed, and the company should document any accepted exception.

### Who decides issue priority?

The delivery team can recommend priority from evidence and affected task. The company owner should approve release risk and tradeoffs.
