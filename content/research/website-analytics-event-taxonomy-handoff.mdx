# Analytics Event Taxonomy Handoff for Web Teams

An analytics handoff should describe what a visitor does, what event is emitted, which parameters are allowed, what consent state applies, and who owns the property. A name alone is not a test plan.

## Key Stats

- Google Analytics 4 uses events to measure interactions (Google)
- WCAG 2.2 has 4 principles (W3C)
- NIST defines least privilege as minimum necessary access (NIST)

## Key Takeaways

- Define an event contract before implementation.
- Test consent and denied-consent states explicitly.
- Keep property ownership and access with the company.

## Methodology

The workflow applies official Google, W3C, and NIST guidance. It does not infer user behavior, attribution, or conversion performance from documentation.

## Event contract

For each event record trigger, name, parameters, allowed values, page context, consent requirement, expected destination, owner, and test evidence. Mark events that are proposed, implemented, tested, accepted, or retired.

## Handoff evidence

Use a test page and controlled actions. Save the event payload, consent state, timestamp, browser, expected result, actual result, and reviewer. Remove temporary access after the company accepts the implementation.

## Frequently asked questions

### Should an event name include page copy?

Prefer a stable name with documented parameters. Copy changes should not silently change the event contract.

### Who owns the analytics property?

The company should own the property and approve access, retention, consent behavior, and data decisions.
