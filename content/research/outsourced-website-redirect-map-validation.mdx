# Redirect Map Validation for Outsourced Website Redesigns

A redirect map is a set of user and search transitions, not a spreadsheet to archive after launch. Every changed URL needs a deliberate destination, a test result, and an owner.

## Key Stats

- HTTP status codes have 5 classes (IANA)
- A sitemap URL entry can contain one loc value (Sitemaps protocol)
- Google documents permanent redirects as part of a site move workflow (Google)

## Key Takeaways

- Inventory old URLs before deleting or renaming pages.
- Map to the closest useful destination, not a generic home page.
- Test redirect chains, targets, canonicals, and sitemap inputs.

## Methodology

This guide uses Google Search Central, IANA, and the sitemap protocol as primary references. The checklist is an operational interpretation for an outsourced redesign and does not predict ranking outcomes.

## Map fields

Include old URL, status, new URL, redirect type, reason, content owner, canonical target, test date, result, and exception. Compare the map with crawls, analytics landing pages, known campaigns, and the existing sitemap.

## Validation pass

Test representative old URLs, query strings, trailing-slash variants, missing pages, and destination responses. Check that the final destination is useful, accessible, internally linked, and not part of a redirect chain.

## Frequently asked questions

### Should every old URL redirect to the home page?

No. Use the closest useful destination, or return an intentional status when no equivalent exists.

### Who approves a redirect map?

The company owner should approve business and content decisions; the production team should supply tests and evidence.
