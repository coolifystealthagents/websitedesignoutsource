# Review Empty States in an Outsourced Website Design Handoff

An empty state is part of the experience, not a blank space waiting for content. It should tell a visitor what is missing and offer a sensible next action.

## Name the reason

Separate a first-use state, a no-results state, a cleared state, and a temporary loading or failure state. Each one needs different language and recovery options.

## Give the visitor orientation

Use a short explanation that matches the visitor’s action. Avoid blaming the visitor or implying that an empty result proves the site has nothing useful.

## Offer one useful next step

Link to a broader search, related category, guide, or return path when it genuinely helps. Do not fill the state with unrelated calls to action.

## Include the state in review

Ask the outsourced team to show empty states on desktop, mobile, keyboard navigation, and with long copy. Keep approved wording with the component or template record.

## Frequently asked questions

### Is an empty state only needed for search?

No. It can appear in dashboards, saved lists, filters, directories, and any experience where content may not yet exist.

### Who writes the message?

The content owner should write or approve it, while the design team ensures the message fits the interaction and layout.
