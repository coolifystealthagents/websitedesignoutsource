# Write a Search Results Page Brief for an Outsourced Designer

**Published: September 1, 2026**

Site search is often reviewed only with a perfect query and a full result set. A useful brief also covers misspellings, empty results, slow responses, long titles, filters, and keyboard navigation.

## Define the search contract

Name the content sources to index, excluded material, update frequency, ranking expectations, result fields, filter behavior, and supported query patterns. Provide representative searches from real user needs. State whether search is delivered by the site platform or an external service and who controls that account.

## Design every result state

- Show loading without hiding the submitted query.
- Explain zero results and offer a useful next step.
- Preserve filters and query text when navigating back.
- Make result count and filter changes understandable to assistive technology.

## Manage risk and ownership

Avoid promising intelligent ranking without a measurable definition. Search logs may contain personal or sensitive text, so analytics access and retention need explicit ownership.

## Define acceptance

Test agreed queries on supported devices, including no-result and error cases. Record expected ranking examples, response behavior, analytics events, and the process for removing stale content.

## Frequently asked questions

### Who should own this record?

A named client owner should approve business rules and access. The outsourced team maintains implementation detail and supplies repeatable evidence.

### When should the team review it?

Review it before implementation, at acceptance, and whenever a related service, policy, account, or production component changes.

### Does a template prove the work is complete?

No. The completed record must match the implemented website and be supported by checks that another reviewer can repeat.
