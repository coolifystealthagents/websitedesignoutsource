# Build a User Flow Map Before Outsourcing Website Design

A user flow map describes how someone moves from a need to a useful outcome. It gives an outsourced design team more direction than a page list because it connects screens to real decisions.

## Name the starting context

Record where a person may arrive, such as a search result, referral, campaign page, or returning visit. Different entry contexts may need different reassurance or navigation.

## Describe the decision points

At each step, state what the visitor must understand or choose. Keep the statement about user intent, not the interface control. This prevents a button label from becoming the whole specification.

## Include alternate paths

Map cases where information is missing, a visitor is not ready, or a requested service is out of scope. These paths often reveal the need for comparison pages, explanations, or a safe return route.

## Turn the map into review criteria

Ask whether each page supports the next decision, whether the route has a clear destination, and whether a visitor can recover from a wrong choice. Review the map alongside the designs.

## Frequently asked questions

### Does a flow map take the place of wireframes?

No. It explains the route and decisions; wireframes explore the page structure that supports that route.

### How detailed should the first map be?

Start with the main user task and a few meaningful branches. Add detail when a branch changes content, access, or approval needs.
