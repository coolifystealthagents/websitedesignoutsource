# Source-File Handoff Rules for Outsourced Website Design

Rendered pages are not enough for a maintainable design handoff. The company should receive the files, links, decisions, and dependencies needed to inspect or change the work later.

## List the source package

Name the editable design file, component library, token reference, image sources, font notes, copy version, route map, and any prototype or annotation links. Record the owner and access location for each item.

## Explain what changed

Return a short change summary that points to the affected pages and components. If a shared component changed, list the other routes that need review. The outsourced website design team should identify intentional exceptions rather than leaving the owner to compare every screen manually.

## Include open decisions

Separate accepted work from sample content, pending approvals, missing assets, and known technical limits. State who can resolve each item. A clean folder with hidden uncertainty is not a complete handoff.

## Verify access

The company should be able to open and copy the sources using named access. Remove temporary access when the project ends according to the owner's policy. Keep the final package in the company workspace, not only in a contributor's account.


## Prove the source handoff works

A source package should let a new contributor identify the editable file, exported asset, font or token dependency, current route, and accepted exceptions. Test it by asking someone unfamiliar with the work to make a safe text change and trace where it appears. If the answer depends on private memory, the handoff is not finished.
