# Brief Modal Dialog Behavior, Not Just Its Appearance

**Published: September 10, 2026**

A polished dialog mockup says little about where focus goes, how Escape behaves, or what happens to unfinished input. Those choices belong in the interaction brief.

## State why a dialog is needed

Use a dialog for a bounded task that must interrupt the current page. Name the trigger, title, initial focus target, primary action, and return-focus target. If the task can work as a regular page, record why interruption is still preferable.

## Define every exit

Specify close button, Escape, backdrop, cancel, successful completion, and navigation behavior. A destructive confirmation should identify the affected item and explain whether the action can be undone. Do not discard entered data without an agreed warning rule.

## Test the interaction loop

Open the dialog with keyboard and pointer. Confirm focus stays inside while it is active, the background is unavailable, error messages are announced, and closing restores focus to a sensible place. Check the on-screen keyboard and zoom on a small device.
