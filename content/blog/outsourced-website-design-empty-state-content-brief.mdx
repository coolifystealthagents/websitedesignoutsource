# Brief Empty States Before They Reach Development

**Published: September 10, 2026**

An empty search result is different from an account with no saved items. One suggests changing a query. The other may need an invitation to begin. A single generic message cannot do both jobs well.

## Name the cause

List each state the interface can reach: no records yet, no match after filtering, unavailable data, and content removed by permissions. Give every state an approved heading, explanation, primary action, and optional recovery link.

## Keep the action honest

The button should address the reason the area is empty. Clear filters when filters caused the result. Create an item when the account is new. Do not promise recovery when the service has failed.

## Supply repeatable fixtures

Give the build team a test account or deterministic data condition for every state. Review the state at desktop and narrow widths, with long translated text if localization is in scope. Confirm that assistive technology receives the updated message after an interaction.
