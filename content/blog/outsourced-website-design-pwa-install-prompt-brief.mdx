# Plan a Respectful PWA Install Prompt

**Published: September 7, 2026**

An install prompt shown on arrival asks for commitment before the visitor has experienced any value. The brief should connect prompting to a useful moment and acknowledge that browser support and installation flows differ.

## Define eligibility and timing

Record the supported browsers, technical install criteria, and product signal that makes the invitation relevant. Good signals may include a completed task or repeated use. Never block the main journey while waiting for an install decision.

## Respect dismissal

Specify how long a rejection suppresses the custom prompt and where installation remains discoverable later. Avoid repeated overlays, misleading urgency, or language that suggests installation is required when the website still works.

## Set accurate expectations

- Name the benefit that is actually available.
- Explain offline behavior without claiming every feature works offline.
- Define updates and stale-content handling.
- Provide an uninstall or reset help route.
- Measure exposure, acceptance, dismissal, and post-install use separately.

## Test the real lifecycle

Check first eligibility, acceptance, dismissal, refresh, browser-managed installation, launch from the installed icon, offline states, and an application update. Record unsupported environments as expected outcomes.
