# Review a Redirect Map Before an Outsourced Website Redesign

A redirect map is more than a list of old and new URLs. It is a decision record for preserving useful paths while an outsourced website design team changes page structure.

## Start with the complete source list

Gather the existing sitemap, crawl results, analytics landing pages, campaign links, and known customer-facing URLs. Normalize trailing slashes, protocols, casing, and query-string rules before reviewing destinations.

## Judge each destination by visitor intent

For every old path, record whether the page remains, moves to a closely related route, or is intentionally removed. A destination should answer the same underlying need, not merely share a keyword.

## Record exceptions clearly

Note chains, loops, retired pages, external destinations, language variants, and paths that must remain unchanged. Give each exception an owner and a reason so it is not silently overwritten during implementation.

## Test the working route

Check representative redirects from desktop and mobile contexts, including old links with common query strings. Confirm the destination loads, the page explains the expected topic, and important forms or navigation paths remain usable.

## Keep the map with the handoff

Deliver the final source list, destination rules, implementation notes, test evidence, and approval record in the company-owned workspace. Review the map again if a page is renamed after approval.

## Frequently asked questions

### Should every old URL redirect to the home page?

No. Send visitors to the closest useful destination. If no relevant destination exists, document the removal rather than creating a misleading catch-all route.

### Who approves the redirect map?

The company owner of the site and search content should approve it. The outsourced team can prepare the map, identify risks, and provide test evidence.
