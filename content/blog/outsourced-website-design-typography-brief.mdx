# What to Include in a Website Typography Brief

Typography decisions affect scanning, layout, and accessibility. A useful brief gives a designer rules to work with, not a list of font names without context.

## Define the hierarchy

Show the relationship between page title, section heading, body copy, labels, links, and supporting text. Include a real content example with a long heading. Short samples hide layout problems.

## Record the approved type choices

Name the fonts, available weights, licensing status, fallback behavior, and where the files live. If the choice is still open, say who approves it. Do not make a designer hunt through old files for the current version.

## Explain responsive expectations

Specify which relationships must remain stable on small screens. Check line length, spacing, buttons, and text that may wrap. A type scale is only useful when it behaves well with actual content.

## Include readable content rules

State how links, captions, labels, and error messages should appear. Make sure color is not the only way to distinguish text or status.

## Frequently asked questions

### Should a typography brief specify exact pixel sizes?

It can specify the intended hierarchy and tested examples. The implementation should also allow text to resize and wrap without losing meaning.

### Who checks the final type treatment?

The person who owns the content should check wording and hierarchy. A design reviewer should check the visual behavior and responsive result.
