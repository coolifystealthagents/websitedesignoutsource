# Map the User Journey Before Outsourced Website Design

A page can be polished and still fail if it appears at the wrong point in a visitor's decision. A small journey map gives an outsourced website designer a view of the questions that surround the page.

## Map moments, not abstract personas

Write the situation that brings someone to the site, the question they need answered, and the next action that makes sense. Use the language customers use in messages or sales calls when it is available. Keep the map tied to a task.

## Check the handoffs

For each step, ask which page, person, or system receives the visitor next. A service page may lead to a comparison, a contact route, or a useful explanation. If the next step is unclear, the designer cannot judge whether a call to action belongs above the fold.

## Give the designer evidence

Attach search queries, support questions, approved copy, or page analytics that support the journey. Label assumptions separately. This keeps an attractive guess from becoming an accidental requirement.

## Review the map with its owner

The map is a decision aid, not a permanent research document. Ask the person closest to the audience to correct it before page layouts begin.

## Frequently asked questions

### Does every page need a journey map?

No. Map the important paths first, especially pages that introduce a service or receive a high-stakes action.

### Can a journey map be a table?

Yes. Columns for situation, visitor question, page, next action, evidence, and owner are enough for many projects.
