# Brief a Data Table That Still Works on a Phone

**Published: September 8, 2026**

A desktop table can hide a rough mobile experience. Columns vanish, controls move away from the row they affect, and long values push the page sideways. Set the information priorities before an outsourced team chooses a responsive pattern.

## Start with the reader's decision

Name the task the table supports. A comparison table, invoice list, audit log, and staff directory need different columns and controls. Rank every field as required, useful, or optional at narrow widths. Include realistic long names, dates, empty values, and status labels in the sample data.

## Choose behavior deliberately

A horizontally scrolling table may preserve relationships better than stacked cards. Cards may work when each row is a self-contained record. Agree on sticky headings, column visibility, sorting, filtering, pagination, and row selection. Keep an action beside the record it changes.

## Test the awkward cases

- Zoom the page and use a narrow viewport.
- Navigate headings, cells, filters, and actions by keyboard.
- Check focus after sorting or changing pages.
- Try long translated labels and unbroken identifiers.
- Confirm empty, loading, error, and no-result states.
- Make selected rows understandable without color alone.

## Record the acceptance evidence

Capture the dataset, viewport, zoom level, browser, input method, and result. A polished screenshot proves appearance at one size. It does not prove that people can understand headers, reach hidden content, or recover after an update.
