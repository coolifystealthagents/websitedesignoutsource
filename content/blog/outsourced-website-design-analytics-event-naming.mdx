# An Analytics Event Naming Brief for Outsourced Web Design

For each event, define the user action, trigger, name, parameters, consent condition, destination, and owner. Tie the event to a page task rather than collecting clicks without a question.

## Avoid ambiguous signals

Distinguish a view from an interaction and a successful completion from an attempt. Document whether repeated actions are expected and how important context is represented.

## Review privacy and evidence

Collect only the information needed for the stated measurement purpose. Test events with representative journeys and hand over the event map with the page and form inventory.

## Frequently asked questions

### Why include this in an outsourced design brief?

It gives the design team a concrete decision context and gives the company a useful way to review the result.

### What should be checked before approval?

Check the source record, rendered page, links, responsive behavior, and the facts or decisions that the page presents.
