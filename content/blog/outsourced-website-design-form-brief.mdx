# How to Brief a Website Form for an Outsourced Designer

Forms fail when the design only shows the empty state. An outsourced website designer needs the task, field rules, messages, and handoff behavior before choosing a layout.

## Define the reason for each field

Write what decision or response each field supports. Remove fields that do not serve the visitor or the receiving team. If a field is optional, explain why it is present.

## Describe the complete journey

Include first visit, keyboard focus, invalid input, server error, successful submission, and the next destination. Provide realistic long values so the layout is tested against the content it will receive.

## Keep privacy language nearby

Record the approved notice, consent behavior, retention explanation, and link to the relevant policy. The designer should not invent legal wording or imply a use that has not been approved.

## Make ownership explicit

Name who owns field labels, validation rules, notification behavior, and the final acceptance decision. This prevents a visual review from hiding a workflow issue.

## Frequently asked questions

### Should a form brief include every backend detail?

Include the behavior the page must communicate and the owner for technical rules. Keep implementation detail in the technical handoff.

### What makes an error message useful?

It should identify the problem in plain language and explain how to correct it without losing entered information.
