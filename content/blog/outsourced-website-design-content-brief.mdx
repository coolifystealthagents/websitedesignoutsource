# How to Write a Content Brief for Outsourced Website Design

A designer can only make good page decisions when the brief explains who the page is for and what it must help them do. A short brief is fine. An incomplete brief is expensive because missing decisions return as revisions.

## Start with the page job

Name the audience, the question they have, and the action the page should support. Avoid vague aims such as "make it look better." Say whether the page should explain a service, collect an enquiry, support a campaign, or help an existing customer.

## Add the decisions a designer needs

Include the approved headline, supporting copy, required sections, brand references, examples to avoid, and any technical limits. Mark each item as approved, proposed, or still open. That lets the designer spend time on layout rather than guessing which text is final.

## Define review boundaries

Name one person who can settle a disagreement. Set the review date and explain what a useful comment looks like. Comments tied to a page area or user task are easier to act on than general reactions.

## Frequently asked questions

### How long should a brief be?

Long enough to record the page job, audience, approved inputs, constraints, and review owner. A focused two-page brief is often more useful than a long document with no decisions.

### Should the designer write the copy?

Agree that before work starts. If copy is still open, label it as draft and give the designer permission to identify layout risks rather than silently rewriting the message.
