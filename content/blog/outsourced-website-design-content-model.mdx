# How to Define a Content Model for an Outsourced Website

A content model turns a collection of pages into a clear set of content types and fields. For an outsourced website design team, it makes the intended structure visible before layouts multiply.

## Start with content types

List the distinct things the site needs to publish, such as service pages, articles, case studies, team profiles, or location pages. Do not create a type merely because two pages look different.

- Name the user purpose
- Record required and optional fields
- Note which fields may be reused

## Connect fields to page decisions

For each field, explain where it appears and what decision it supports. A short summary field may serve a card, while a longer introduction may establish context on the detail page.

## Assign ownership

Give each type a content owner and a design owner. The external team can implement the pattern, while the company retains authority over claims, approvals, and ongoing maintenance.

## Test the model with real examples

Use a representative page set rather than invented filler. Check whether the model handles short titles, long titles, missing optional fields, and future additions without awkward exceptions.

## Frequently asked questions

### Who should approve a content model?

The company owner of the content should approve the meaning and ownership rules, while the design team can advise on presentation and reuse.

### Should every page use the same fields?

No. Shared fields are useful where the user need is shared. Forcing unrelated pages into one shape usually creates confusing optional fields.
