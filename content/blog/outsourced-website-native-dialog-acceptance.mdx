**Published: October 12, 2026**

## Define the visitor outcome

Native Dialog Acceptance for Outsourced Interfaces treats dialog acceptance as an observable client acceptance question, not a screenshot preference. At checkpoint 1, identify confirmation and help flows, the approved requirement, affected route, viewport or input state, expected result, and accessibility owner. Record WD-B-outsourced-website-native-dialog-acceptance-1 so another reviewer can repeat the decision.

The define the visitor outcome checkpoint runs the focus and dismissal test on an assembled route, with checkpoint-specific attention to confirmation and help flows and dialog acceptance. Exercise ordinary, narrow, keyboard, zoom, error, empty, and returning-visitor states where they apply. Preserve browser, version, content fixture, result, defect owner, due point, and retest evidence under WD-B-outsourced-website-native-dialog-acceptance-1.
