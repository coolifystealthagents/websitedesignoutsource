# Write a Header Navigation Brief for an Outsourced Website

The header is a high-impact route into the site. A brief helps an outsourced design team treat navigation as an information architecture decision rather than a collection of links.

## Prioritize visitor tasks

List the destinations that support the site’s main audiences and decisions. Do not give every internal page equal prominence in the primary menu.

## Choose understandable labels

Use words visitors recognize and test them against the destination pages. If a label needs explanation, the information architecture may need another review.

## Define responsive behavior

Record how the menu opens, closes, receives focus, handles long labels, and exposes nested routes on narrow screens. Include the keyboard path in the brief.

## Keep ownership visible

Name who approves menu changes and who maintains destination links. Review the header when page architecture changes, not only during a redesign.

## Frequently asked questions

### Should the header link to every service?

Only when the set is small and each destination supports a primary visitor task. Otherwise use a clear grouping or supporting page.

### What should be tested on mobile?

Test opening, closing, focus order, scroll behavior, long labels, nested routes, and whether the visitor can return to the page they were viewing.
