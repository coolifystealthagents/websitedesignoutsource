# Create a Review Library for Outsourced Website Design

Recurring website work benefits from a small library of accepted examples. It should help a designer answer a current question, not become a museum of every screen the team has seen.

## Save decisions with examples

For each pattern, record its purpose, page context, approved state, and owner. A screenshot without the decision behind it can encourage the wrong reuse.

## Include known limits

Note content length, mobile behavior, accessibility checks, and cases where the pattern should not be used. Clear limits are more useful than a large gallery.

## Review before reuse

Check whether the new page has the same audience and task. If not, treat the example as evidence rather than a template. Record the reason when a variation is accepted.

## Maintain a short index

Use plain names and archive obsolete patterns. Assign an owner who can remove examples that no longer describe the current site.

## Frequently asked questions

### Should every accepted screen enter the library?

No. Save patterns that recur or teach a decision the next project will need.

### Who maintains the library?

Name an owner who can approve additions and mark examples obsolete. Shared ownership without a final decision maker leads to clutter.
