# Set a Content Freeze Plan for an Outsourced Website Launch

**Published: September 2, 2026**

A content freeze is a controlled period for reconciling source and destination systems before launch. It should not mean that important corrections disappear into private messages or that urgent business updates wait without an escalation path.

## Define what is frozen

List the included sites, languages, page types, files, metadata, navigation, and structured data. Record the start time, expected end, source-of-truth system, freeze owner, and people authorized to approve exceptions.

## Create an exception route

- Describe what qualifies as urgent.
- Capture the requested change and affected routes.
- Assess whether migration work must be repeated.
- Record approval and implementation location.
- Retest both source and destination where relevant.

## Reconcile before release

Compare the final inventory with the built site. Check additions, edits, removals, redirects, metadata, links, assets, and dates made during the freeze window. Assign every mismatch a disposition instead of relying on the newest timestamp alone.

## Close the freeze explicitly

Announce which system is authoritative after launch, reopen normal editing permissions, and preserve the exception log with release evidence. Document any deferred items, owner, and target date so the freeze does not become a hidden backlog.

## Frequently asked questions

### How long should a content freeze last?

Use the shortest window that allows a reliable reconciliation for the actual migration scope.

### Can urgent corrections still be made?

Yes, through a documented exception path that updates all affected systems and evidence.
