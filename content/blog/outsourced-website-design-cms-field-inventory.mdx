# Building a CMS Field Inventory for an Outsourced Website

For each content type, record field name, purpose, required state, length guidance, formatting rules, example value, and display location. Include who owns the field and how it should be reviewed.

## Design for the editor

Use fields that reflect meaningful content decisions rather than visual fragments. Explain which fields combine into a component and which are intentionally independent.

## Test representative entries

Populate short, long, missing, and unusual values before approving the template. Check headings, metadata, links, and responsive behavior with real content shapes.

## Frequently asked questions

### Why include this in an outsourced design brief?

It gives the design team a concrete decision context and gives the company a useful way to review the result.

### What should be checked before approval?

Check the source record, rendered page, links, responsive behavior, and the facts or decisions that the page presents.
